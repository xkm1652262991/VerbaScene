# 版本采用与重新生成

## 基本原则

- 页面自由进入，没有阶段确认。
- 模型输出先成为候选。
- 用户采用候选后，它成为该资源键的当前版本。
- 重新生成创建新版本，不覆盖历史。
- 上游变化不删除下游，只标记 Prompt 或成片可能过期。

## 同资源并发

同一角色状态、场景状态、道具状态或视频片段已有活动任务时，新的重复提交返回冲突。其他资源仍可编辑和生成。

## Prompt

人工编辑的 `Shot.video_prompt` 始终保留。预览接口可返回当前上游重新编译后的候选 Prompt；只有显式调用编译接口才覆盖编辑稿。

## 审计

生成任务保存最终 Prompt、引用资产、输入指纹、Provider、模型和能力快照。版本采用记录在资产与运行审计中，不改变页面可访问性。

## 剧本多 Agent 审稿与修订

- 综合审稿器只产出结构化问题，不直接改稿。问题包含类别、严重度、场号、证据、修复指令和必须保护的元素。
- `must_fix` 允许触发一次 Targeted Reviser；`editorial_note` 只供人工参考。
- Reviser 只返回 `scene_replacements`、已解决/未解决问题代码和保护元素声明。后端拒绝重复场号、未知场号和审稿范围外的替换。
- Patch 调用失败或合同无效时保留结构有效的初稿，并标记 `needs_attention`；审稿不可用时标记 `review_unavailable`。两者都不伪装成质量通过，也不形成阶段门禁。
- 最终合同报告是确定性校验结果，不使用模型总分、字数、句数或固定场景数作为质量代理。
