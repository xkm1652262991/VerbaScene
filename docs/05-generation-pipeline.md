# 生成流水线设计

## 1. 目标与边界

当前流水线面向单集动画启蒙英语短剧。它把 AI 创意描述或已有剧本转换为英语剧本、结构化资产、视频片段和可导出的成片。

本轮不实现多集模型、独立 TTS、独立音效生成或 Seedream 真实适配器。视频槽位
接入火山方舟 Seedance 2.0；工程验收使用 Mock HTTP 合同，不自动提交真实付费
生成任务。

视觉风格采用单一事实源：`Project.style` 保存用户明确选择的风格标签，
`creative_settings.animation_style` 只保留兼容镜像。当前默认标签为
“高品质风格化三维儿童动画”，运行时由确定性编译器展开为可执行的三维造型、
材质、光照、景深和跨镜头一致性规则。用户明确选择二维或其他风格时必须原样尊重，
不能被默认值覆盖。

实体参考图 Prompt 和分镜图 Prompt 只保存主体、动作、空间、构图与状态事实；
图片 Provider 调用时才把当前项目风格组合进去。视频 Prompt 是可编辑的最终编译产物，
其中可以包含展开后的视觉风格。项目风格变化时保留历史资产并把已有视频 Prompt 标记为过期，
不得继续静默发送旧风格 Prompt。

## 2. 顶层工作区

```text
剧本 <-> 资产库 <-> 视频制作
```

三个页面始终可进入。业务动作只校验自身必需输入，不读取上一阶段是否 `approved`。同一资源已有活动生成任务时拒绝重复提交，但其他资源和页面继续可用。

`ProjectStage` 与 `/workflow/gates` 不再是运行依赖。`ProjectStageRun` 继续保存操作审计，按以下类别归档：

- `script`
- `assets`
- `production`
- `export`

## 3. 创作输入与剧本

### 3.1 AI 创意模式

- `Chapter.input_mode=ai_brief`
- 创意描述必填，导入剧本可空。
- 故事开发阶段依据创意描述和英语等级建立人物欲望、具体阻碍、因果节拍、结尾兑现和自然的英语交流机会；不读取受众年龄，也不要求用户先填写教学表格。

### 3.2 导入剧本模式

- `Chapter.input_mode=imported_script`
- 导入剧本文本必填，创意描述可空。
- 故事开发阶段优先忠实保留事件、角色关系、因果、结局和对白意图，只补足动画呈现所需的连接。

两种模式都使用同一质量流水线：

```text
持久化排队 -> StoryBlueprint -> ScriptDraft -> ScriptReview -> 可选 ScriptPatch -> ContractReport -> FinalScript
```

综合审稿把问题归入 `causality`、`character`、`dialogue`、`continuity` 或 `production`，并以 `must_fix` / `editorial_note` 区分是否允许自动修订。修订 Agent 只返回被授权场景的替换对象，后端按场号合并；未点名场景不得改变。故事开发或审稿不可用时保留可用稿并记录降级；初稿无法解析时只做一次内容保持不变的结构恢复。

最终 `quality_gate` 只表达事实：`pass`、`needs_attention` 或 `review_unavailable`。它不锁定资产库和视频工作区。

两种模式都输出：

- 中文制作描述和可见动作。
- A1 英文角色对白。
- 可选中文释义。
- 情绪与结构化音效提示。
- 可读剧本和结构化 `scenes` / `dialogues`。

生成程序不按输入字数猜时长，不按台词字数、句数、固定场景数或 Prompt 字符数拒绝作品。程序只保留下游必须的最小结构合同。

## 4. 资产库

实体提取产生角色、场景和道具。角色默认只生成一张 `base` 多视角设定图，包含正面、侧面、四分之三侧和稳定外观特征。尴尬、道歉、用力推车等 `state_variants` 仅保留为剧情状态文本，由对应片段 Prompt 描述，不独立生成角色状态图。

场景如确有昼夜、季节或破损等持续视觉变化，可继续使用稳定 `variant_key` 管理独立状态图：

- `base`：基础形象。
- 其他稳定键：剧情状态形象，例如 `muddy`、`raincoat`。

媒体 `version` 表示同一形象的重新生成版本，不得代替 `variant_key`。采用新版本只更新当前选择，旧版本继续可读。旧项目已有的角色状态图保留历史记录，但不再进入默认工作台和新视频引用。

## 5. 视频片段与内部节拍

`Shot` 表示一个可独立调用视频模型的片段。`Shot.shot_card` 保存多个内部镜头节拍：

```json
{
  "schema_version": 3,
  "beats": [
    {
      "beat_id": "beat-1",
      "camera": "中景，缓慢推进",
      "action": "Milo 指向红色小球。",
      "dialogue_ids": ["dialogue-id"],
      "sound_cues": ["轻柔室内环境音", "小球弹跳声"]
    }
  ],
  "prompt_fingerprint": "sha256:...",
  "prompt_stale": false
}
```

LLM 不再输出 `Shot.duration_sec`。内部 beats 只表达剧情和镜头推进顺序，不分配秒数。每条 Dialogue 必须绑定到对应片段和节拍。

新分镜方案采用“长片段、内部多镜头”：

- 每个 Shot 默认包含 2–4 个内部镜头，允许景别、机位和镜头运动变化。
- 普通动作、反应、对白轮次和景别变化留在同一 Shot 的 beats 中。
- 场景/时空改变、连续性断裂、主要资产集合明显变化或单次生成无法自然承载完整动作时才创建新 Shot。
- 程序根据整集目标和 Provider 有效范围计算建议片段数量；LLM 只能在此范围内组织叙事，不能猜每段具体秒数。
- Seedance 默认使用 `provider_auto`；其他 Provider 没有智能时长能力时继续使用其确定性参数合同。

## 6. 最终视频 Prompt

确定性 Prompt 编译器将以下内容编译到一份镜头优先的 Seedance 式最终提示词：

- 明确启用时的片段首帧，以及角色和场景的“图片N”素材定义。
- 参考图已定义角色、场景和道具外观时只写“图片N=名称”的绑定，不重复资产百科；
- 道具只在所属镜头的剧情动作和空间关系中出现；没有动作使用的道具不进入 Prompt。
- 内部镜头按“镜头1、镜头2……”自然推进，每个镜头只表达一个主要运镜。
- 具体身体动作、幅度、速度、动作过渡和可见情绪表现。
- 片段时长由 Provider 智能选择或人工固定覆盖，不在 Prompt 中写死片段总秒数和内部镜头时间区间。
- 英文对白、说话人和情绪。
- 环境、动作和拟声音效提示。
- 从 `Project.style` 编译得到的一行视觉风格标签；画幅、分辨率和时长由 Provider 参数控制。
- “生成原生对白与音效”的音频要求。
- “画面不得出现字幕、标题、气泡文字或其他可读文字”的约束。

最终 Prompt 不向模型暴露项目侧内部 `@资产名`，只使用 Provider 能理解的
“图片N”素材序号，并在开头把素材定义为稳定的角色/场景称呼。图片、视频、音频
分别按精确引用顺序编号；Seedance 的 `content` 数组必须使用同一顺序，不能只靠
自然语言名字猜测素材对应关系。对白使用 `{台词}`，音效使用 `<音效>`，不要求
内部镜头精确占用第几秒。

编译器按任务、参考绑定、镜头块和全局约束组织内容。角色、场景、道具和状态描述按语义去重，不按固定字符数裁剪；Prompt 质量问题必须描述为事实冲突、引用错绑、内容重复、不可执行动作或多重峰值竞争，不能只报告“太长”。

视频参考图遵循“少而明确”：默认只使用角色图最多 2 张和场景图最多 1 张。用户
明确启用首帧时再增加 1 张首帧，总图片数最多 4 张。道具图和角色多角度源图不进入
视频请求，避免素材特征竞争；道具只由片段剧情和动作文字控制。

`Shot.video_prompt` 是用户可编辑且实际发送的最终稿。上游输入变化时只把 `prompt_stale` 标记为 `true`，保留原稿。只有用户点击“重新编译 Prompt”才覆盖该字段。

字幕导出优先使用 Dialogue 的明确起止时间；未设置时，按片段总时长和内部镜头顺序均分生成可编辑的兜底时间窗，不读取历史 `beats[].duration_sec`。

每次生成任务保存：

- 最终 Prompt。
- 引用资产及具体版本。
- 输入指纹。
- Provider 与模型。
- Provider 能力快照。
- 原始响应和输出资产。

## 7. Provider 能力合同

视频 Provider 对外声明：

- `native_audio`
- `reference_images`
- `reference_videos`
- `reference_audio`
- `multi_reference`
- `smart_duration`
- `min_duration_sec / max_duration_sec`
- `supported_resolutions`

业务层根据能力决定可传入的参考类型，不按 Provider 名称猜测能力。
`seedance2_api` 通过方舟异步任务接口消费精确绑定的图片、视频和音频参考，并
默认生成原生音轨。Seedream Adapter 留到后续。

`min_duration_sec / max_duration_sec` 是固定时长的硬能力合同。`smart_duration` 表示 Provider 能自行选择时长；工作台默认使用智能模式，只在人工固定覆盖时执行上下限校验。不得静默截断、压缩节拍或把一个片段自动变成多个无法追溯的远端任务。

## 8. 过期传播

脚本、Dialogue、资产选择或片段节拍变化时：

1. 计算新的输入指纹。
2. 将相关 Prompt 或产物标记为“可能过期”。
3. 保留现有 Prompt、图片、视频和采用状态。
4. 等用户主动重新编译或重生成。

过期状态只提供决策信息，不改变页面可进入性。

## 9. 导出

导出请求包含 `subtitle_mode=none|en|bilingual`，默认 `none`。

FFmpeg 合成流程：

1. 按片段顺序解析当前采用的视频版本。
2. 保留每个片段的原生音轨。
3. 对无音轨片段补等长静音流。
4. 统一视频/音频编码参数后拼接。
5. 从当前 Dialogue 时间轴生成临时字幕。
6. `en` 烧录英文，`bilingual` 烧录英文和可选中文释义，`none` 不烧录。
7. 写入版本化 `final_export` Asset 与 Export 审计。

旧 TTS 文件不自动物理删除，但不会出现在工作台、生成链路或新导出链路。

## 10. 当前执行与恢复边界

- 剧本、反思式分镜导演、单镜头视频、视频重生成和项目视频批次由统一本地任务运行时执行。
- `GenerationTask` 是后台任务真相源；`ProjectStageRun` 只是工作区操作审计。
- 只有明确未被 Provider 受理的可重试错误自动重试一次。其他失败由用户显式人工重试或重新生成。
- 成功候选和历史正式资产保留。
- 剧本和分镜导演从阶段检查点续跑；已受理视频从远程任务 ID 续轮询。分镜草案提交结果不确定时任务失败，审稿或 Patch 提交结果不确定时降级保留已有有效草案，任何路径都不盲目重提。
- 图片生成和 FFmpeg 导出仍为同步 API，不在统一任务运行时内。
