项目名称：**VerbaScene（语境片场）—— AI 英语动画短剧生产工作台**

项目性质：个人项目或核心项目经历；是否写“独立完成”应按真实协作情况决定。

> 面向动画英语短剧制作的 AIGC 工作台，将创意或已有剧本转化为可编辑剧本、角色与场景资产、视频片段和带字幕成片，并支持生成任务恢复、候选版本采用与局部返工。

## 四、针对不同岗位怎么微调

### 后端开发岗位

把统一任务运行时放在第一条，重点保留这些词：数据库真相源、条件领取、租约、心跳、幂等、唯一约束、短事务、父子任务、提交状态不确定。

面试时重点讲：

1. 为什么不能用“先查询、再插入”防重复提交。
2. Provider 超时为什么不等于未收到请求。
3. 为什么远端任务 ID 落库后只能继续轮询。
4. 为什么网络等待期间不能长期持有数据库事务。

### AI 应用开发岗位

把反思式分镜导演 Agent 放在第一条，重点保留这些词：冻结输入、结构化产物、确定性校验、Reflection、受限 Patch、检查点恢复、人工采用。

面试时重点讲：

1. Agent 的边界为什么停在可编辑分镜，不自动调用付费视频生成。
2. 为什么只有 `must_fix` 才触发一次修订。
3. 为什么规则校验和原子保存不能交给 LLM 自由决定。
4. 旁白为什么属于说话人但不属于可视角色资产。

### 偏全栈岗位

保留前端任务适配和版本工作台：生成接口返回 `202 + GenerationTask`，前端展示真实任务阶段、取消/重试、导演检查报告、候选采用、历史版本和成片下载，不把 HTTP 请求成功误当成内容生成成功。

## 五、STAR 法则如何对应简历内容

### S：背景

AI 视频生成耗时长、结果不稳定且可能产生费用；剧本、参考资产和视频又存在多个版本。原有内存队列在进程重启、重复点击和批量生成时难以保证状态一致。

### T：目标

在不提前引入 Celery、Redis 和微服务的单机部署范围内，完成任务持久化、恢复、去重、取消、批量执行以及生成结果的可追溯返工。

### A：行动

- 统一 `GenerationTask` 状态和 Handler 协议，让数据库成为任务真相源。
- 使用条件更新领取任务，以租约和心跳识别失联 Worker。
- 用数据库唯一约束治理活动资源冲突，用 `Idempotency-Key` 识别客户端重试。
- 将异步 Provider 拆成 `submit / poll / cancel / fetch_result`，在外部调用前后写入短事务检查点。
- 用冻结快照、结构化合同、Reflection 和受限 Patch 构建可恢复的分镜 Agent。

### R：结果

剧本、分镜和视频长任务具备统一的查询、恢复、取消和人工重试语义；同一资源的活动任务无法并发重复创建，已受理的远端任务可以在重启后继续轮询。当前后端全量 235 项自动化测试通过，并已有约 32.5 秒真实多片段样片证据。

## 六、30 秒口述版

> 我做的项目叫 VerbaScene，是一个 AI 英语动画短剧生产工作台。它不是输入 Prompt 就返回视频的页面，而是把剧本、角色和场景资产、视频候选以及最终导出组织成一条可编辑、可返工的工作流。我主要做了两块：一套数据库持久化的长任务运行时，解决重启恢复、重复提交、取消和批量任务；以及一个反思式分镜导演 Agent，用结构化合同和确定性校验约束模型只做一次定点修订。项目现在能用 Docker 一键启动，后端 235 项测试通过，但仍定位为单机工程项目，不会把它说成生产级分布式 SaaS。
